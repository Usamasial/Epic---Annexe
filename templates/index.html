History & Connectivity retention

Publish throttle (reading rate vs. publish rate)

When enabled, a parameter is published at most once per its publish interval, tracked separately for every meter and parameter (so kWh never blocks MD, volt or amp). The interval is taken from the parameter (Parameters tab), else the meter, else the ZLAN default (ZLANs & Meters tab). Readings that come sooner are dropped.

Backup (CSV files on this gateway)

…

Readings, connectivity events and delivery results are appended to daily files under the backup folder (one folder per month). They survive history purges and database resets. Writing pauses automatically if free disk space gets low.

Connectivity debounce

Local Connectivity history always records every event -- this only limits how often flapping status changes are pushed to MQTT/HTTP.

Connectivity heartbeat

If a meter or ZLAN's status hasn't changed in this many hours, its current status is re-sent as a fresh signal -- so a long-stable (or long-stuck) connection still shows recent proof-of-life instead of a stale multi-day-old entry.

Modbus polling (RS-485/ZLAN tuning)

Applies to newly (re)started ZLAN connections — restart the app for a change to take effect on ZLANs already polling.
